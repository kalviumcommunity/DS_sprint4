PART D: SEPARATION OF CONCERNS - VERIFY DATA FLOW
================================================================================

Physical Separation:

□ Are data files completely separate from code files?
  Example structure:
  ✓ data/
     ├── raw/
     └── processed/
    scripts/

  ✗ WRONG:
    ├── sales.csv (data mixed with code)
    ├── analysis.py
    └── processed_sales.csv

□ Is processed data separate from output artifacts?
  ✓ Good:
    ├── data/processed/features.csv
    └── outputs/models/model.pkl

  ✗ Bad:
    ├── data/processed/features.csv
    ├── data/processed/model.pkl (model != dataset)
    └── data/processed/plot.png (visualization != dataset)

Output Organization:

□ Are outputs organized by PURPOSE (not by date)?
  outputs/
  ├── models/          (trained ML models)
  ├── visualizations/  (plots and charts)
  └── reports/         (analysis summaries)

  Not:
  outputs/
  ├── 2024_01_15/
  ├── 2024_01_16/
  └── 2024_01_17/

File Types Verification:

□ Can I describe the difference:
  
  RAW data file:
  - Type: CSV, JSON, Excel
  - Purpose: Original from source
  - State: Unmodified
  - Example: sales_transactions_raw.csv

  PROCESSED data file:
  - Type: CSV, JSON
  - Purpose: For analysis/modeling
  - State: Cleaned, transformed
  - Example: features_engineered.csv

  OUTPUT artifact:
  - Type: .pkl (models), .png (viz), .html (reports)
  - Purpose: Results/deliverables
  - State: Generated by code
  - Example: model_v2.pkl, sales_trend.png

PART J: COMMON MISTAKES - CAN YOU IDENTIFY THEM?
================================================================================

Mistake 1: Modifying Raw Data

Scenario: You load raw data and clean it:
```python
df = pd.read_csv('data/raw/sales.csv')
df.drop_duplicates(inplace=True)
df.to_csv('data/raw/sales.csv')  # ← BIG MISTAKE
```

□ Can I identify why this is wrong?
  - Overwrites original data
  - No backup if mistake made
  - Cannot prove data authenticity
  - Defeats purpose of keeping raw

□ Can I correct it?
  - Load from data/raw/
  - Create new dataframe:  df_clean = df.drop_duplicates()
  - Save to data/processed/: df_clean.to_csv('data/processed/sales_cleaned.csv')

Mistake 2: Mixing Outputs with Data

Scenario: Project structure:
```
data/
├── sales.csv
├── model.pkl        ← Model in data folder!
└── plot.png         ← Visualization in data folder!
```

□ Can I identify organizational problem?
  - Outputs (models, plots) mixed with data
  - No separation of concerns
  - Hard to find things
  - Unclear what is data vs. result

□ Can I reorganize it?
  outputs/
  ├── models/model.pkl
  └── visualizations/plot.png

Mistake 3: Unclear File Names

Scenario: Your processed folder has:
```
data/processed/
├── data.csv
├── data_v2.csv
├── data_final.csv
├── cleaned.csv
└── output.csv
```

□ Can I identify the problem?
  - Names don't tell you what's inside
  - Unclear which is "final"
  - Multiple "versions" but purpose unknown
  - Cannot track evolution

□ Can I improve naming?
  - sales_cleaned.csv (clear: cleaned)
  - sales_merged_customers_v2.csv (clear: merged + version)
  - customer_features_engineered.csv (clear: features added)

Mistake 4: No Documentation

Scenario: Your processed data folder:
```
data/processed/
├── features.csv
├── train.csv
├── test.csv
```

No metadata, no README, no documentation.

□ Can I identify the problem?
  - Cannot tell where data came from
  - Unknown what transformations applied
  - No reproducibility
  - New team member confused

□ Can I add documentation?
  - Create features_metadata.txt
  - Create train_metadata.txt, test_metadata.txt
  - Create README.md in processed/
  - Document split strategy

Mistake 5: Data Modified Unexpectedly

Scenario: Raw data downloaded 2 weeks ago:
- 100,000 records
- Used in analysis
- Now downloading again
- 95,000 records
- Results don't match!

□ Can I identify the issue?
  - Source data changed
  - Analysis based on outdated raw data
  - No backup of original
  - Cannot reproduce original results

□ Can I prevent this?
  - Download with date: sales_2024_01_15.csv
  - Document: "This analysis uses 2024_01_15 extract"
  - Keep multiple date versions if critical
  - Version control snapshots

Mistake 6: Unclear Processing Steps

Scenario: Someone asks:
"I need to use this processed data. What was done to it?"

Your answer:
"I cleaned it"

Bad answer! Unclear.

□ Can I provide better answer?
  - Removed X duplicate rows (identifiers: [list])
  - Filled Y null values using [strategy]
  - Modified Z records due to [reason]
  - Result: 95,000 records from 100,000
  - Metadata file: See processed_metadata.txt
