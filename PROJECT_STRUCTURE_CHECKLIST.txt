PROJECT STRUCTURE CHECKLIST
===========================

Milestone 7: Creating a Project Folder Structure for Data Science Work
Comprehensive verification guide for project organization best practices

============================================================================
PART A: KNOWLEDGE ASSESSMENT
============================================================================

☐ I understand why project structure matters
  - Improves team collaboration
  - Enables reproducible analysis
  - Facilitates code reuse
  - Looks professional

☐ I can explain the principle of separation of concerns
  - Raw data is separate from processed data
  - Code is separate from data
  - Generated outputs are separate from source data

☐ I know which folders are immutable vs. generated
  - IMMUTABLE: data/raw/
  - GENERATED: data/processed/, outputs/

☐ I understand naming conventions for folders
  - Lowercase with underscores
  - Singular for data folders (data/, not datas/)
  - Plural for collections (notebooks/, outputs/)

☐ I can identify what data belongs where
  - Raw data in data/raw/
  - Processed data in data/processed/
  - Reference data in data/external/

☐ I know the difference between notebooks and scripts
  - Notebooks: Exploration and prototyping
  - Scripts: Reusable, production-ready code

☐ I understand the purpose of outputs folder
  - Models: Trained models
  - Visualizations: Charts and plots
  - Reports: Analysis summaries

☐ I can explain why raw data should never be modified
  - Preserves reproducibility
  - Provides audit trail
  - Safe backup

☐ Root folder contains README.md
☐ Root folder contains .gitignore
☐ Root folder contains clear, lowercase folder names
☐ No unnecessary files in root directory

☐ data/ folder exists

☐ outputs/ folder exists
☐ All folders at same directory level

REQUIRED FOLDERS - TIER 2 (Standard):
☐ data/raw/ subfolder exists
☐ data/processed/ subfolder exists
☐ outputs/models/ subfolder exists
☐ outputs/visualizations/ subfolder exists
☐ outputs/reports/ subfolder exists
☐ scripts/ folder exists
☐ configs/ folder exists
☐ docs/ folder exists (recommended)

OPTIONAL FOLDERS - TIER 3 (Advanced):
☐ data/external/ for reference data
☐ tests/ for unit tests
☐ logs/ for application logs

============================================================================
PART C: DATA FOLDER VERIFICATION
============================================================================

data/raw/:
☐ Contains ONLY original, unmodified source data
☐ Has README.md explaining data sources
☐ No cleaned or processed versions here
☐ No transformation scripts modify files here
☐ Data preserved exactly as received

data/processed/:
☐ Contains cleaned, analysis-ready data
☐ Files named with transformation info
  Example: sales_cleaned_duplicates_removed.csv
☐ Has README.md documenting processing steps
☐ Does NOT contain raw data
☐ Does NOT contain temporary files

data/external/ (if exists):
☐ Contains reference data (lookup tables, calendars)
☐ Properly labeled and sourced
☐ Documented in README.md

============================================================================
PART D: CODE ORGANIZATION VERIFICATION
============================================================================

notebooks/:
☐ Uses numbered prefix naming convention
  Format: 01_exploratory_analysis.ipynb
  ✓ (01_, 02_, 03_)
  ✗ (analysis.ipynb, analysis_v2.ipynb, final.ipynb)

☐ No more than one version of each analysis
  ✗ AVOID: 01_eda.ipynb, 01_eda_v2.ipynb, 01_final.ipynb
  ✓ USE: 01_eda.ipynb (improve in place, use git)

☐ Each notebook has a clear, descriptive title
  ✓ 01_exploratory_analysis_customer_data.ipynb
  ✗ 01_analysis.ipynb, 01_notes.ipynb

☐ Notebooks contain Markdown and Code cells
☐ Code cells are focused, not 1000+ lines

scripts/:
☐ Contains reusable Python functions
☐ Functions have docstrings
☐ One purpose per file when practical
  ✓ data_cleaning.py, feature_engineering.py
  ✗ main_script.py (does everything)

☐ Functions are imported in notebooks
  NOT copy-pasted across notebooks

☐ Function names are descriptive
  ✓ remove_duplicates(), engineer_features()
  ✗ clean(), process()

☐ Imports organized: stdlib → third-party → local

============================================================================
PART E: OUTPUTS FOLDER VERIFICATION
============================================================================

outputs/models/:
☐ Contains serialized model files (.pkl, .h5, .joblib)
☐ Model files have descriptive names
  ✓ model_random_forest_tuned.pkl
  ✗ model.pkl, model_v2.pkl

☐ Includes model metadata if applicable
☐ Does NOT contain notebooks or data

outputs/visualizations/:
☐ Contains generated plots (.png, .pdf, .svg)
☐ Plot files have descriptive names
  ✓ correlation_heatmap_features.png
  ✗ plot1.png, chart.png

☐ All plots generated by code (not manually created)
☐ High resolution for publication (dpi ≥ 300)

outputs/reports/:
☐ Contains analysis summaries
☐ HTML/PDF reports or CSV exports
☐ Files named specifically for content
  ✓ model_performance_report.html
  ✗ report.html

☐ Reports are professional and clear

============================================================================
PART F: CONFIGURATION AND DOCUMENTATION
============================================================================

configs/:
☐ Contains configuration files (YAML/JSON)
☐ Includes major configuration types
  ☐ data_config.yaml (data sources)
  ☐ model_config.yaml (hyperparameters)
  ☐ feature_config.yaml (feature definitions)

☐ Configuration files are tracked in git
☐ Sensitive data (passwords, keys) in .env (NOT tracked)

docs/:
☐ Contains documentation files
☐ Includes data_dictionary.md
  ☐ Describes every column
  ☐ Explains data types
  ☐ Documents missing values

.gitignore:
☐ Exists in root directory
☐ Ignores large generated files (*.pkl, *.png)
☐ Ignores processed data
☐ Ignores environment files (.env)
☐ Does NOT ignore scripts/ or configs/ or notebooks/
☐ Does NOT ignore data/raw/

README.md:
☐ Exists in root directory
☐ Explains project purpose
☐ Shows folder structure diagram
☐ Includes quick start instructions
☐ References where to find data and outputs
☐ Explains how to run analysis

============================================================================

Folder names:

☐ Plural for collections (...outputs/, not output/)
☐ Descriptive words
  ✓ customer_segments/, processed_data/
  ✗ data2/, proj_files/, new_folder/

File names:
☐ Descriptive and specific
  ✓ sales_data_2024_cleaned.csv
  ✗ data.csv, file001.csv

☐ Include what was done when applicable
  ✓ customer_data_duplicates_removed.csv
  ✗ data_processed.csv

☐ For notebooks: numbered prefix (01_, 02_, 03_)
  ✓ 01_exploratory_analysis.ipynb
  ✗ analysis.ipynb, eda_v2.ipynb

☐ For models: include model type and status
  ✓ model_linear_regression_baseline.pkl
  ✗ model.pkl, model_final.pkl

PART H: SEPARATION OF CONCERNS VERIFICATION
============================================================================

☐ Raw and processed data in different folders
☐ Exploratory code (notebooks) separate from production code (scripts)
☐ Generated outputs separate from source data
☐ Configuration separate from code
☐ Documentation separate from analysis code

☐ Raw data NEVER modified
☐ Scripts are NEVER run directly in notebooks
  (Functions imported from scripts instead)

☐ Processed data ALWAYS generated from raw data
  NOT manually edited or stored

☐ Outputs ALWAYS generated by code
  NOT manually created or stored

PART K: COMMON MISTAKES CHECKLIST
============================================================================

❌ AVOID: Mixing raw and processed data
   ✓ Instead: Separate into data/raw/ and data/processed/

❌ AVOID: Multiple notebook versions (v1, v2, final)
   ✓ Instead: Single current version, use git history

❌ AVOID: Code duplicated across notebooks
   ✓ Instead: Extract to scripts/, import in notebooks

❌ AVOID: Everything in one folder
   ✓ Instead: Logical separation (data/, notebooks/, outputs/)

❌ AVOID: Unclear folder names
   ✓ Instead: Descriptive, lowercase, underscores

❌ AVOID: Outputs stored in data/ folder
   ✓ Instead: outputs/ folder with subfolders

❌ AVOID: No documentation
   ✓ Instead: README.md and data_dictionary.md

❌ AVOID: Storing secrets in code
   ✓ Instead: Environment variables or .env files

❌ AVOID: No .gitignore
   ✓ Instead: .gitignore excludes large files

❌ AVOID: Hardcoded file paths in scripts
   ✓ Instead: Configuration files or function parameters
