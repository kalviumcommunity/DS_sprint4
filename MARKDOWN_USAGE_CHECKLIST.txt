PART A: KNOWLEDGE ASSESSMENT
================================================================================

[ ] Understand Markdown syntax basics
    - Markdown is text formatting that renders as styled output
    - Backticks create monospace code formatting
    - Triple backticks create code blocks

[ ] Know the six heading levels
    - # is Level 1 (main title)
    - ## is Level 2 (major section)
    - ### is Level 3 (subsection)
    - Don't skip levels (don't go from # to ###)

[ ] Understand when to use ordered lists
    - Use when order matters or showing steps
    - Use for procedures, workflows, processes

[ ] Understand when to use unordered lists
    - Use when order doesn't matter
    - Use for features, requirements, options, requirements

[ ] Know inline code vs code blocks
    - Inline: `single backticks` for short code in text
    - Blocks: triple backticks for multi-line examples

[ ] Understand Markdown placement strategy
    - Markdown cell BEFORE code cell explains what will happen
    - Markdown cell AFTER code cell explains results/meaning
    - Professional pattern: Markdown → Code → Markdown

[ ] Know why documentation matters
    - Helps readers understand notebook purpose and flow
    - Makes notebooks collaborative and maintainable
    - Professional presentation of analysis

PART I: COMMON ISSUES AND FIXES
================================================================================

Issue: "I don't have enough lists in my notebook"
Solution:
  - Review the guide: places where lists should go include
    - Requirements or features (unordered)
    - Steps in a process (ordered)
    - Verification criteria (unordered)
  - Break up complex explanations into bulleted lists
  - Add at least one ordered list and one unordered list

Issue: "My code block doesn't show syntax highlighting"
Solution:
  - Verify triple backticks: ``` (not two or four)
  - Specify language: ```python (not ```Python or missing)
  - Test in different platforms (GitHub, Jupyter, VS Code)

Issue: "Headings appear, but hierarchy seems wrong"
Solution:
  - Count the # symbols (# is level 1, ## is level 2, ### is level 3)
  - Verify no levels are skipped (don't jump from # to ###)
  - Ensure parallel concepts use the same level

Issue: "I'm not sure where inline code is needed"
Solution:
  - Use backticks for: variables (`x`), functions (`print()`), parameters (`sep=','`)
  - Don't use for: regular words, complete sentences with code
  - Rule of thumb: If it's Python syntax, use backticks

Issue: "Video is running too long"
Solution:
  - Target: 2 minutes ±10 seconds (acceptable range: 1:50-2:10)
  - If too long: reduce explanation detail or speak faster
  - If too short: add more detail to scenario answer
  - Use script timing as reference

Issue: "Scenario answer doesn't mention Markdown techniques"
Solution:
  - Reference at least 2 of: headings, lists, inline code, code blocks
  - Connect to the problem: "Without headings, readers couldn't find sections"
  - Explain the fix: "Better Markdown would add clear headings and explanations"
